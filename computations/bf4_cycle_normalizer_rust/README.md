# BF4 sparse cycle normalizer pilot

This dependency-free Rust executable benchmarks the exact polynomial
comparison exposed by
`BF4ExactSpatialTreeGaugeTranslationSemantics.lean`.

It copies the literal 26-vertex path table and 23-chord table, constructs the
adapted 48-quaternion words, and compares exact sparse integer polynomials:

```text
P(start) * U_c * conjugate(P(end))
```

against the multiplication order generated by the selected-pair ledger.  A
monomial uses four packed bits for each of the 192 real coordinates;
coefficients use checked `i64` arithmetic.  No floating-point arithmetic or
third-party crate is involved.

Run:

```sh
cargo run --release
cargo run --release -- --cycle 0
cargo test --release
```

On the 2026-08-03 development Mac, cycle 0 normalized in under one
millisecond, versus the stopped Lean canonical reduction that had produced no
result after one minute.  All 23 cycles passed in 1.399 seconds.  The deepest
cycles produced 131,072 canonical terms in each vector component and took
about 0.45 seconds apiece.  The release test suite repeated the all-cycle
comparison in 1.24 seconds.

The CSV digests are deterministic regression fingerprints, not proof hashes.
The exact Rust equality is likewise an oracle result, not a Lean theorem.  A
load-bearing use must either:

1. emit a derivation certificate checked by a small constructive Lean checker;
   or
2. replace the expansion with structural Lean proofs of quaternion
   conjugation reversal and selected-translation composition.

The second route is likely smaller.  This pilot establishes that Rust is a
practical generator/oracle for the concrete 23-cycle and later cutoff scans.
