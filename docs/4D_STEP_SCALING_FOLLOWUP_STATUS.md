### Stage E result (final, 2026-10-17 23:15 PDT) and ERRATUM on the two-loop reference
**Erratum (found 23:15 PDT while finalising E).** In the Stage C text and in the 22:40 partial E note above I used a first-order two-loop reference with b1 = 34/(3 (16 pi^2)^2), i.e. missing the SU(N) factor N^2 = 4. The correct SU(2), N_f=0 two-loop coefficient is b1 = (136/3)/(16 pi^2)^2 = 0.001818 (matches `B2 = 136/3` in `stepscale.py`). With d(1/g2)/dlnL = -(2 b0 + 2 b1 g2) integrated exactly over L -> 2L, the two-loop step-scaling shift s = 1/u - 1/Sigma is: u=1.54: 0.0685, 1.6: 0.0686, 2.0: 0.0698, 2.35: 0.0708, 2.4: 0.0710, 2.5: 0.0714 (one-loop: 0.0644). So the two-loop shift exceeds one-loop by 6% (u~1.5) to 10% (u~2.4), not by 1.5–2.3% as I wrote. (The truncated series `sigma_twoloop` in `stepscale.py` and the statement in `4D_STEP_SCALING_RESULTS.md` that one-/two-loop differ by < 1.1% refer to Sigma, which differs by <~2% — in the shift 1/u - 1/Sigma, which is what is measured, the difference is 6–10%, and the truncated u^3 series underestimates it: 0.0674 vs 0.0710 at u=2.4.) Consequently the Stage C statement "data cannot discriminate one-loop from two-loop" and the 'consistent with two-loop-like 0.0654–0.0659' wording are **superseded** by the numbers below. The comparison tables `E_pair.md`, `E_forms.md` use the exact two-loop shift. ### Step 2 (Zeuthen flow): code, verification and CPU-hour estimate (written BEFORE the MC launch, 19:20 PDT)
**Code (own file `src/bin/su2gf.rs`; the Wilson-only output is bit-identical to the previous binary for the same seed, checked with `cmp`):** option `--zeuthen 1` additionally flows every measured configuration with the **Zeuthen flow** of Ramos–Sint (arXiv:1508.05552, eq. (5)): dV V^+/dt = -g0^2 (1 + (a^2/12) nabla*_mu nabla_mu) d_{x,mu} S_LW[V], S_LW = tree-level Lüscher–Weisz (c0 = 5/3 plaquettes, c1 = -1/12 for all 1x2/2x1 rectangles; 18 rectangle staples per link) with the covariant Laplacian acting on the Lie-algebra-valued force by parallel transport, same Lüscher RK3 integrator; output `NAME.zeu.csv` (same columns: clover E_c, plaquette E_p, Q at each flow time), measured on the SAME configurations as the Wilson flow in `NAME.csv` (so Wilson–Zeuthen differences are configuration-correlated). Observable = clover E (not the 1x2-improved E; the tree-level a^2 effect of the clover E is removed by the normalisation below, not by the operator). Self-tests (`--selftest 4`): sum over links of a0(U C_rect) = 6 x sum over rectangles of a0(R) to 3e-13 (staples complete and correctly oriented), gauge covariance of the force max|Z' - gZg^+| = 4e-15, flowed E_c gauge invariant to 4e-16. **Tree-level normalisation for the Zeuthen flow** N_zeu(c,L) (`analysis/zeuthen_norm.py`: exact free-field mode sum with the linearised LW force and D = 1 - phat^2/12; the same code with D = 1, H = H_Wilson reproduces gfana.N_lat to 1e-12): N_zeu/N_lat = 0.83/0.85 (L=6, c=0.3/0.4), 0.93/0.95 (L=12), 0.98/0.99 (L=24). **Check at weak coupling (L=6, beta=2000, 1500 meas):** g2/(4/beta) = 1.0031(18) (Wilson, N_lat), 1.0044(21) (Zeuthen, N_zeu) at c=0.3; 0.990(4), 0.993(4) at c=0.4 (Zeuthen with the wrong N_lat would give 0.83). **Integration step:** eps=0.1 changes t^2E by ~1.2e-4 (relative, same for both flows; effect on a pair shift ~ 0.064 x 1.2e-4 = 8e-6) w.r.t. eps=0.04 (0.08: 6e-5; 0.12: 2e-4; 0.04 vs 0.02: 1e-5), so eps = 0.1 is used for both flows in the new runs. **Observed (not expected) feature:** the clover E has an O(a^2) error of the opposite sign to the Wilson-flow error, so with the Zeuthen flow the tree-level a^2 deviation of N from its continuum value is ~3.5x LARGER than with the Wilson flow (N_zeu/N_cont - 1 = -0.026 at L=24, c=0.3 vs -0.0074 for Wilson); after dividing by the exact N this does not matter at tree level, but it means this test cannot be expected to remove the O(a^2 g^4) effects unless the observable is improved too (1x2-improved E not implemented).
